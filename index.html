O que mudou

Um editor mais moderno para projetos OpenTibia

O foco foi melhorar o fluxo de trabalho sem perder compatibilidade com o ecossistema do NexaMap: Classic/TFS, ClientID, Canary/Crystal e diferentes recursos de servidor.

◫

Novo Workspace

Cliente e servidor agora fazem parte de um workspace persistente. O editor detecta mapas, items.otb, items.xml, monsters, NPCs e appearances automaticamente.

＋

Abas independentes

Cada mapa pode manter sua própria sessão de recursos. É possível trabalhar com clientes/servidores diferentes sem recarregar ou quebrar as abas já abertas.

⇄

Cross-Client Copy & Paste

Copie áreas entre clientes diferentes. O NexaMap compara gráficos, metadados e estrutura dos itens, mostra o que foi encontrado, remapeado ou está faltando antes do paste.

⌘

Command Palette

Busca rápida de comandos para acessar ferramentas sem ficar procurando em menus. Mais velocidade para quem usa o editor todos os dias.

★

Favorites 2.0

Favoritos persistentes e separados por sessão de recursos, com categorias e previews. Brushes e itens ficam mais rápidos de encontrar.

⌖

Novo Minimap

Minimap dockável, mais bonito e útil para navegação. Inclui viewport, controles e suporte a markers de ActionID e UniqueID.

✓

Map Diagnostics

Scanner de saúde do mapa para localizar problemas e navegar diretamente até as ocorrências, com filtros, progresso e cancelamento seguro.

▶

Playtest Mode

O antigo In-game Preview evoluiu para um modo de teste mais completo, com movimento, HUD, iluminação, interação e efeitos atmosféricos.

⚡

Renderer e caches

Revisões por chunks 4×4, cache de geometria CPU, cache persistente de ground na GPU e controle de atlas foram integrados preservando o renderer atual.

☁

Multiplayer em tempo real

Host/Join com snapshot, transações, revisões, locks, permissões, chat, cursores, pings, aprovações, reconexão e resync.

▣

Tooltips e containers

Preview de containers e informações de Item ID, ActionID e UniqueID foram melhorados. Os overlays continuam legíveis mesmo em zoom distante.

◉

Collections inteligente

A Collections Palette agora respeita os recursos ativos e deixa de mostrar um painel vazio quando não existem collections válidas.

Destaque

Multiplayer pensado para edição real

  • Host autoritativo com revisões por transação.
  • Conflitos de edição são validados em vez de depender apenas da ordem de chegada.
  • Locks de regiões e permissões por participante.
  • Snapshot inicial + journal para reconexão e resync.
  • Autenticação por desafio HMAC; senha não é enviada em texto puro.
  • Interface com Host/Join, participantes, chat, pings e aprovações.
  • Porta multiplayer dedicada padrão: 49171.
Mapear junto deixou de ser só uma ideia.

O objetivo é permitir que duas ou mais pessoas trabalhem no mesmo mapa com uma base muito mais segura que um simples “enviar tiles pela rede”. O NexaMap valida sessão, revisão, locks, conteúdo e permissões antes de aplicar alterações.

Fluxo de trabalho

Menos atrito para quem trabalha com vários projetos

Antes

  • Dados duplicados por várias versões.
  • Mudar recursos podia exigir reload completo.
  • Copiar entre clientes diferentes era arriscado.
  • Ferramentas importantes ficavam espalhadas nos menus.
  • Collections podia aparecer vazia.

Agora

  • data/editor concentra os materiais compartilhados.
  • Cada aba pode ter uma sessão independente.
  • Cross-client paste tem análise e confirmação antes de aplicar.
  • Command Palette e Favorites aceleram o acesso.
  • Palettes e recursos acompanham corretamente a sessão ativa.
Auditoria e estabilidade

🛡

⏱

Sem delete em thread solta

O descarte pesado do Editor agora usa uma fila controlada e joinável em vez de uma thread detached sem rastreamento.

◇

Callbacks endurecidos

Callbacks diferidos que podiam sobreviver à janela foram protegidos com referências fracas e nova validação antes do acesso.

▧

OpenGL teardown

O encerramento de frames e recursos GL foi corrigido para evitar término duplicado e manter o contexto correto durante a destruição.

↯

Clipboard sem prender sessão

O clipboard cross-client deixou de manter uma sessão antiga inteira viva apenas porque havia conteúdo copiado.

⌫

Código duplicado removido

Guards redundantes e owners manuais substituídos foram removidos sem apagar APIs apenas porque pareciam não utilizadas.

What changed

A more modern editor for OpenTibia projects

The goal was to improve everyday workflows while preserving compatibility across the NexaMap ecosystem: Classic/TFS, ClientID, Canary/Crystal, and different server resources.

◫

New Workspace

Client and server resources now belong to a persistent workspace. The editor automatically discovers maps, items.otb, items.xml, monsters, NPCs, and appearances.

＋

Independent tabs

Each map can keep its own resource session. You can work with different clients and servers without reloading or disrupting tabs that are already open.

⇄

Cross-Client Copy & Paste

Copy areas between different clients. NexaMap compares graphics, metadata, and item structure, then shows matched, remapped, and missing resources before pasting.

⌘

Command Palette

Quick command search gives direct access to tools without hunting through menus, making frequent editing actions faster.

★

Favorites 2.0

Persistent favorites are separated by resource session and include categories and previews, making brushes and items easier to find.

⌖

New Minimap

A dockable minimap improves navigation with viewport controls and support for Action ID and Unique ID markers.

✓

Map Diagnostics

A map health scanner finds problems and navigates directly to occurrences with filters, progress reporting, and safe cancellation.

▶

Playtest Mode

The old in-game preview evolved into a richer local test mode with movement, HUD, lighting, interaction, and atmospheric effects.

⚡

Renderer and caches

4×4 chunk revisions, CPU geometry caching, persistent GPU ground caching, and atlas tracking were integrated while preserving the current renderer.

☁

Real-time multiplayer

Host and Join sessions include snapshots, transactions, revisions, locks, permissions, chat, cursors, pings, approvals, reconnection, and resynchronization.

▣

Tooltips and containers

Container previews and Item ID, Action ID, and Unique ID information were improved. Overlays remain readable at distant zoom levels.

◉

Smarter Collections

The Collections Palette now follows the active resources and stays hidden when no valid collections are available.

Highlight

Multiplayer designed for real editing

  • An authoritative host tracks revisions for every transaction.
  • Edit conflicts are validated instead of relying only on arrival order.
  • Region locks and per-participant permissions protect shared work.
  • An initial snapshot and journal support reconnection and resynchronization.
  • HMAC challenge authentication means the password is never sent as plain text.
  • The interface includes Host/Join, participants, chat, pings, and approvals.
  • Default dedicated multiplayer port: 49171.
Mapping together is no longer just an idea.

The goal is to let two or more people work on the same map with stronger safeguards than simply sending tiles over the network. NexaMap validates the session, revision, locks, content, and permissions before applying changes.

Workflow

Less friction when working across multiple projects

Before

  • Data was duplicated across many versions.
  • Changing resources could require a full reload.
  • Copying between different clients was risky.
  • Important tools were scattered across menus.
  • Collections could appear as an empty panel.

Now

  • data/editor centralizes shared materials.
  • Every tab can use an independent session.
  • Cross-client paste includes analysis and confirmation.
  • Command Palette and Favorites speed up access.
  • Palettes and resources follow the active session.
Audit and stability

There was also major cleanup under the hood

After the features were built, the branch received a focused audit of ownership, callbacks, threads, sockets, memory, and OpenGL. The goal was to fix proven problems without refactoring only for appearance.

🛡

Safer lifetimes

Manual MapTab reference counting was replaced with explicit ownership using shared and unique pointers where they accurately represent the design.

⏱

No detached deletion

Heavy Editor disposal now uses a controlled, joinable queue instead of an untracked detached thread.

◇

Hardened callbacks

Deferred callbacks that could outlive their windows now use weak references and validate current state before accessing objects.

▧

OpenGL teardown

Frame and GL resource shutdown was fixed to prevent duplicate end-frame work and keep the correct context current during destruction.

↯

Clipboard releases sessions

The cross-client clipboard no longer keeps an entire old session alive only because copied content still exists.

⌫

Duplicate code removed

Redundant guards and superseded manual owners were removed without deleting APIs simply because they appeared unused.
